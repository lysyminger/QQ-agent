# 本地改动说明（lysy-mods 分支）

这个分支是 [K0nd1us/QQ-agent](https://github.com/K0nd1us/QQ-agent) 在 `fdfd325`（v0.4 Preview，还带 SnowLuma 集成的版本）之上的本地改造，机器人在群里叫「喵喵」。上游之后把项目挪进了 `0.4/`、`0.5/` 两个目录，并移除了 SnowLuma 集成；这里的机器人还靠 SnowLuma 跑，所以没有合并上游，分支起点停在 `fdfd325`。

内容分三块：

- **核心改动**：`src/`、`ui/` 里的修复和新能力。
- **插件**：`plugins/` 里的插件，只收自己写或本机定制的。
- **测试和脚本**：`test/`、`scripts/` 下的文件。

---

## 一、核心改动

### 合并转发

| 改了什么 | 为什么 |
|---|---|
| 取转发内容时先按消息号取，失败再按转发卡片里的 id 取（`onebot.js` 的 `fetchForwardNodes`），收消息和 `read_forward` 都用它 | SnowLuma 上同一条转发，按消息号取经常报 `payload is empty`，按卡片 id 却能取到。原来只用消息号，存档里一半以上的转发没展开；改完后把 26 条没展开的重新取了一遍，全部能展开 |
| 转发里的照片按顺序写成 `[图片1] [图片2]…`，媒体按同样顺序存；`get_message_images` 加 `index` 参数单看第 N 张；不带 `index` 时一次最多看 6 张 | 转发里可能有几十张图，原来一次全下，而且模型不知道哪张是哪张 |
| 转发里的图片链接过期时，`get_message_images` 会重新取一次转发、换上新链接再试（`store.updateByMid` 加了 `replaceMedia`） | QQ 图片链接放久了会失效 |
| 转发里的发言人不再写占位 QQ 号 `1094950020`，多个名字共用一个号时也不写号 | SnowLuma 给转发里每个人都填同一个假号，会让模型把不同的人当成同一个人 |
| 默认人设里"合并转发看不了内容"那句改成"用 read_forward 展开" | 原句和系统提示矛盾，模型会直接说看不到 |

### 表情包

| 改了什么 | 为什么 |
|---|---|
| 新配置 `sticker.minGapMinutes`：同一个聊天两张表情包之间至少隔几分钟，默认 0（不限），设置页"表情包"卡片里可以改 | "积极程度"只是提示词引导，压不住刷屏；这是 `send_sticker` 的硬性限制，间隔内调用会被拒，模型改用文字回 |
| 备注以 `【别发】` 开头的收藏表情不列进提示词和 `list_stickers`，也发不出去 | 收藏里有些图只想留着不想发（比如低俗文字图），不用为此删收藏 |

### 收消息和引用

- **主人不受白名单限制**：`owner-identity` 里配置的主人 QQ，在没加白名单的群里也能叫到机器人，拍一拍也一样。只放行主人本人；黑名单照样生效。
- **引用块用本地存档的正文**：比如 `[视频:标题]`、卡片展开的标题，比 `get_msg` 回来的 `[video]` 有用。`get_msg` 失败时也能从存档里补出引用。引用块带上被引用消息的 `#id`。
- **以文件形式发的照片也能看**：比如原图、电脑拖进来的 `IMG_xxx.JPG`，会换成直链放进 media，`get_message_images` 能看到。
- **补记不是程序自己发的消息**：在手机 QQ 上用机器人号发的、或者外部脚本直接调接口发的，都会补记成"自己说的话"（已读、不触发回复），免得机器人不知道自己说过。sender 留档和回显同时到时只保留一份。
- **自己发的图片也留档**：`get_message_images` 读机器人自己发的图时，优先读本地落盘的文件，不怕链接过期。

### 模型与路由

- **新能力 `llm.agent-backend`**：插件可以接管一次模型调用（codex-bridge 用它把本机 Codex 当"大脑"）。接管失败会自动退回配置里的普通模型。核心导出 `AGENT_BACKEND_SUPPORTED` 供插件判断。
- **`llm.endpoint-pick` 多传了 `messages` 和 `context`**：按难度选模型的路由插件可以据此判断，只看 model 的旧插件不受影响。
- **顶栏显示模型路由状态**：插件通过 `status.*` 能力上报 `route` 字段，顶栏和设置页侧栏显示当前在用哪个模型、为什么用它，每 5 秒刷新一次。
- **价格表加了 GPT-6 系列**：模型名 `Codex gpt-6-luna·xhigh` 这类写法会统一成 `codex/gpt-6-luna` 再查价，前后端同步。

### 联网抓取（safe-fetch）与搜图

- **Clash 等代理的 fake-ip 不再被当成内网**：域名解析到 198.18.0.0/15 时放行，直接写这个 IP 仍然拦截。原来开着代理时，QQ 图片和 B站图片全都下不了。
- **响应自动解压**：gzip / deflate / br 压缩的响应会先解压。B站等站点不管请求头怎么写都回压缩数据。
- **调用方传的参数真正生效**：`safeFetch` / `safeFetchBinary` / `safeFetchBinaryToFile` 的 `headers`、`timeoutMs`、`maxBytes` 以前被静默忽略，现在会用上。跨域重定向时会去掉 Cookie / Authorization 头。
- **搜图更准**：
  - Bing 搜索页为空时改用它的 async 接口，页面读取上限提高到 3MB。
  - 百度适配改版后的小写字段。
  - 两边都带回图片来源页的标题和地址。
  - 新增 B站专栏图搜，带节流和风控冷却。
  - `search_images` 的结果附上来源标题，提示模型优先挑标题对得上的图。
- **自定义搜索服务的摘要不再丢失**：`content` 为空串时会退回用 `summary`。

### 其它修复

- `chatActive.ttlMinutes` 单位算错的问题：原来任何设置都会变成 1000 小时，一进活跃期就几乎出不来。
- 插件目录监听改为文件真的变了才热重载：Windows 上杀毒、索引服务扫描目录也会触发监听事件，以前会把正在运行的插件拦腰打断。
- 提示词里"回复保持简短"改成"长短看情况"：别人认真问、要信息时把内容说足。

## 二、插件（plugins/）

插件放进 `plugins/` 就会被热加载，不用重启。下面是这个分支收录的插件：

| 插件 | 做什么 |
|---|---|
| codex-bridge | 主人在 QQ 里使唤本机 Codex CLI。也可以把 Codex 当机器人的"大脑"，qq-agent 的工具、插件、档位全部保留。附带：画图参考图、听视频、B站专栏、群文化学习、自动语音梗、学校周边"吃什么"自动推荐（数据来自高德，见下文脚本） |
| forward-summary | 有人要求时总结合并转发和聊天截图（图片识别 + 本地 OCR） |
| addressee-guard | 判断一句话在叫谁，别抢不属于自己的话 |
| reply-freshness / reply-window | 群里刷得快时提醒机器人引用旧消息；刚聊完的人接着说话时继续接话 |
| send-pacing / typing-indicator / typo-sim | 按字数一句一句地发；私聊显示"正在输入"；偶尔手滑打错字再撤回 |
| sleep-schedule | 到点睡觉，消息照存，醒了接着看 |
| knowledge-base / kb-autolearn | 本地知识库；遇到不认识的词后台联网查证、写进知识库 |
| group-learner / cross-chat-people-group / qq-identity / owner-identity | 群文化记忆、跨会话认人、名字和 QQ 号对照、主人识别 |
| qq-card-reader / long-image-reader / media-download / speech-to-text-qq | 还原 B站 / 小程序卡片；长截图分段识别；B站 / 抖音视频下载；QQ 原生语音转文字 |
| msg-reaction / netease-song-id / probability-reply / sticker-restraint | 贴表情回应；网易云搜歌；被戳一戳按概率回应；收到表情包只当语气读 |
| inner-os / auto-clean / qq-file-intake / self-tools | 不说话时把心里话发给指定的人；按规则清理存档；QQ / 微信文件收件箱；机器人自己写的工具 |
| zjsru-failover / zjsru-no-think | 浙江树人学院免费模型网关的路由：日常走免费模型，难题走 DeepSeek 官方，带故障切换；关闭免费模型的长时间思考 |
| ark-garrison | 明日方舟"卫戍协议"陪玩（开发中，只有底层和测速脚本） |

**没有上传的插件**：本机还在用，但它们是别人写的，没带许可证，所以不放进这个仓库。需要的话请找原作者。

| 插件 | 作者 |
|---|---|
| adaptive-group-style、live-context、repeat-echo | DSH |
| burst-merge | QQ Agent + DSH |
| inner-life、life-memory、quote-reply | 小肥鱼 |
| meme-tracker | 白空朔 |

本机对 repeat-echo 有一处小改动，同样没有上传：codex-bridge 已经替某条"吃什么"推荐过店时，复读机跳过那条，不再跟着复读。

**插件依赖 `data/` 下的本地数据**，这些数据都不进版本库：

- **吃什么推荐**要先生成店单：在 `data/codex-bridge/food/amap.json` 里填自己的高德 Web 服务 Key（`{"amapKey": "..."}`），再运行 `node scripts/build-campus-guide.mjs`。这一步约调用 70 次高德接口。之后机器人只读本地生成的 `shops.json`，不再调接口。
- **自动语音梗**要有语音库：放在 `data/knowledge-base/voices/`。

## 三、测试和脚本

| 文件 | 说明 |
|---|---|
| `test/forward-sticker-test.mjs` | 合并转发的两种取法、图片编号、按 index 看图、链接过期后重新取转发、占位 QQ 号；表情包【别发】和最小间隔。全部用假 OneBot，不连 QQ |
| `test/food-pick-test.mjs` | "吃什么"的识别、挑店、推荐话术，以及只回一条、不重复推荐。用假发送器，需要先生成店单 |
| `test/voice-auto-trigger-test.mjs` | 自动语音梗的触发和冷却。需要语音库 |
| `test/codex-bridge-fixes-test.mjs` | codex-bridge 的一组回归测试，有几项要联网。带 `LIVE` 的实机项会真的给主人私聊发消息，所以要设置 `QQ_AGENT_OWNER=主人QQ` 才会跑 |
| `scripts/build-campus-guide.mjs` | 从高德拉取学校周边的店和设施，生成 `shops.json` 和两篇知识库词条。加 `--offline` 用已存的原始数据重新生成，不调接口 |

`test/selftest.mjs` 会加载 `plugins/` 下的全部插件。装了 send-pacing 这类会延迟发送的插件时，它会在"等待会话结束"那步超时，这和本分支的改动无关。

## 四、新增 / 变化的配置项

| 配置 | 默认值 | 说明 |
|---|---|---|
| `sticker.minGapMinutes` | `0` | 同一个聊天两张表情包的最小间隔（分钟），0 = 不限。本机用的是 30 |
| `owner-identity` 插件的 `ids` | 空 | 填了之后，主人在没加白名单的群里也能叫到机器人 |
| 收藏表情备注以 `【别发】` 开头 | — | 这个表情不列给模型，也发不出去 |
