# 提示词怎么写

这个机器人每说一句话，背后都是一份临时拼出来的提示词。这份文档讲三件事：提示词由哪几块拼成、哪几块归你写、怎么写才有效。每一段在代码里的位置和顺序，见 [extend_development/prompt-pipeline.md](extend_development/prompt-pipeline.md)。

---

## 一、一份提示词由哪几块拼成

每来一批新消息，程序新开一次会话，模型那边**没有上一轮的记忆**（Codex 大脑除外，见第五节）。发给模型的是：

```
系统提示（src/prompt.js 的 buildSystemPrompt）
  1. 身份句            你是「{botName}」，一个混在 QQ 群里的普通群友……
  2. 安全规则          固定，不能覆盖
  3. 工作方式          固定，不能覆盖（send_message 协议、分条规则）
  4. 反 AI 味 / 主体性 / 该说不该说 / 像真人 / 引用与点名 / 记忆 / 表情包 / QQ 场景 / 汇报禁令
                       固定文案，其中参与度、表情包档位、看图、联网几行跟着设置变
  5. 可用技能          插件和技能的 prompt.sections，按 priority 从高到低
  6. 管理员附加规则    persona.customRules，有才拼

用户消息（buildUserPrompt）
  【角色设定】         persona.roleText，就是你写的角色卡
  【可用表情包】       收藏表情 + 备注
  【引导说明】
  【记忆】【过去状态】【本次新消息】……  越往下变得越快
```

你能写的是这几处：

| 写在哪 | 改什么 | 在哪改 |
|---|---|---|
| `persona.botName` | 机器人名字。也用来判断有没有人叫它 | 设置 → 人设 |
| `persona.roleText` | **角色卡**，最主要的一块 | 设置 → 人设 |
| `persona.participation` | 参与度：安静 / 普通 / 活跃 | 设置 → 人设 |
| `persona.customRules` | 附加规则，排在系统提示最后 | 设置 → 人设 |
| `personaByChat[群号]` | 某个群单独用一套角色卡（先关掉「为所有的群聊/私聊使用同一个人设」） | 设置 → 人设 |
| owner-identity 的 `personaRoleText` / `personaCustomRules` | 主人说话时换的人设和规则 | 插件 → owner-identity |
| 插件 / 技能的 `prompt.sections` 和工具描述 | 某个功能怎么用 | 扩展自己的清单和代码 |
| `persona.systemPromptOverride` | 高级：整个替换第 4 段（安全规则和工作方式仍然强制追加）。占位符 `{botName}` `{roleText}` `{participation}` | 设置 → 人设 →「系统提示词覆盖（高级 · 可选）」 |

人设生效的优先级：**主人专属人设 > 某个群的人设 > 全局人设**。`botName` 和群名片永远用全局的，不然 @ 判断会对不上。

## 二、角色卡怎么写

默认角色卡「小鲸鱼」在 `src/personas.js`，可以当模板。建议照它的分节：

```markdown
# 角色卡：<名字> —— QQ 群友版

## 一、你是谁
一两段：身份、性格、口头禅、雷点、跟群里谁熟。
最后一句写最高原则，比如「先像群友、像真人，再谈人设」。

## 二、群聊说话铁律
编号列出 10~20 条硬规矩：多长、什么时候接话、什么时候闭嘴、被怼怎么办、被问事实先查。

## 三、说话方式
短句、口语、少用括号和句号、不要客服腔……

## 四、节奏与消息习惯
一句一条（send_message 传数组）、可以改口补刀、话说一半先等……

## 五、示例
几组「群友说 → 你回」，比形容词管用得多。
```

几条从实际调教里得出的经验：

1. **规则写成能照着做的样子。** 「回复简短」不如「默认 1~10 字，别人认真问、要信息时把内容说足」。只说「别太长」，模型会连该说清楚的事也憋成一句。
2. **要压过默认行为的规则，放在角色卡第一节。** 系统提示里有一套「反 AI 味」「别当群管家」的固定规则，角色卡又在用户消息开头；两边打架时，模型倾向听写得早、写得具体的那条。比如喵喵的「群友主动要求被骂时可以嘴毒」，放在人设第一节、写清底线，才真的生效。
3. **写清例外和底线，不要只写「不要」。** 「不怼人」会让它连群友主动要的玩笑也拒绝。改成「平时温和；有人主动要被骂可以骂，连发 2~3 条、每条换一个点；不碰地域、民族、性别、外貌缺陷、家人；对方真难过就收」，它才知道边界在哪。
4. **给示例，少给形容词。** 「傲娇」「毒舌」这种词模型会演过头。三组真实的问答示例比一段性格描写有用。
5. **工具的用法写进角色卡要和工具名一致。** 比如「想多说几句，用 send_message 传数组分几条发」「不想接话就直接结束，什么都不发」。别写「（潜水）」这类括号动作，模型会真的把括号发出去。
6. **别和系统提示重复。** 安全规则、发消息协议、表情包怎么发已经在系统提示里了，角色卡里再写一遍只会多花 token，写得不一样还会打架。
7. **改完先看会话页。** 控制台「会话」页每张卡片都有这次的完整提示词、思考过程和工具调用。行为不对时，先找到是哪一句让它这么做的。

## 三、给插件 / 技能写提示词

扩展有两种方式影响提示词（完整说明见 [skill-development.md](extend_development/skill-development.md)）：

**1. 工具描述**：`registerTool({ description, parameters })`。这是模型决定什么时候调用这个工具的**唯一依据**，写清两件事：做什么、什么时候用。

```js
description: '把咒术回战·新宿决战那段固定文案一字不差地发到当前聊天里。'
  + '当群友的发言提到「咒术回战」「新宿」「五条悟」……等相关词时调用。'
  + '注意：文案由本工具直接发送，调用后不要再复述、改写或另发一遍。'
```

（摘自本仓库的 `skills/jujutsu-kaisen-reply/`。）参数的 `description` 也要写，比如「聊天记录里的 #数字」。工具会把东西直接发出去时，一定写上「调用后别再自己说一遍」。

**2. 提示词片段**：清单里的 `prompt.sections`（固定内容），或者导出 `promptSections(context)`（每轮现算）。

```json
"prompt": {
  "sections": [
    { "id": "my-note", "title": "某某功能", "priority": 60, "content": "……" }
  ]
}
```

- `priority` 越大越靠前，上限 99；不管多大都排在核心规则之后，安全规则压不过。
- **每轮会变的内容放 `promptSections(context)`，而且 priority 要低**，排在最后。系统提示前面一段不变，模型服务商的前缀缓存才能命中；把会变的东西插在中间，后面整段缓存全废，钱多花好几倍。
- 返回空字符串就不拼，没事别每轮塞一段「本轮无事」。

## 四、喵喵分支里几处现成的写法

| 位置 | 做什么 | 可以参考的点 |
|---|---|---|
| `plugins/codex-bridge/brain.js` 的 `PREAMBLE` | Codex 大脑的开场说明 | 先说清「你在哪、输入是什么、哪些系统提示里的话在这里不成立」，再列具体做法：不认识的词先查、画角色先拿参考图、说事实前先 `double_check` |
| `plugins/codex-bridge/food.js` 的 `foodHint` | 程序已经替它推荐过店时提醒它 | 告诉模型「程序已经做了什么、别重复做」，比让它自己判断可靠 |
| `plugins/ark-garrison/codex-fast.js` 的 `BASE` | 打游戏时的系统提示 | 只有一句：「你在替人操作手机游戏《明日方舟》，看截图和文字，严格按给定的 JSON 格式回答，不调用任何工具」。规则资料按需拼进用户消息，只带画面上出现的那几个干员 |
| `plugins/ark-garrison/turn.js` | 休整期一回合问一次 | 模型只回操作清单（buy / sell / deploy / ready…），程序执行后核对，失败带新局面再问。能写死的规则（费用 ≤2 就升级、两张同名买第三张）程序直接做，不交给模型 |
| `plugins/ark-garrison/knowledge/` | 游戏资料 | `00-速查.md` 每步都带；其余按画面上出现的名字挑行。`learned.md` 是它自己学到的，规则类必须有画面原文和截图证据，防止把猜的当事实记下 |

共同的思路：**能写死的交给程序，要理解的才交给模型；交给模型的那部分，告诉它现在是什么情况、程序已经做了什么、它只需要决定什么。**

## 五、Codex 大脑的提示词有什么不同

普通模型每次都是全新会话、全量提示词。Codex 大脑（codex-bridge 的 `brain` 模式）是一条长期对话：

- 开新对话时，`PREAMBLE` + qq-agent 的系统提示作为 `developerInstructions` 只给一次。
- 之后每轮按段落比对上一轮，只发新增或变化的行（新消息、心情、今日生活），人设和规则不再重复。
- 上下文超过 `brainRolloverTokens`（默认 15 万）、工具或规则变了、换模型时，换一条新对话。换之前旧对话先写一份交接摘要，新对话开头带上，答应过的事、刚被纠正的事不会忘。

所以改了角色卡或插件的提示词之后，要在「Codex」页对应聊天那一行点「重置」，或者等它自己换新对话，新规则才会生效。

## 六、改完怎么验证

```bash
npm run test:prompt      # 提示词拼接的自测：段落顺序、覆盖模式下安全规则还在、缓存前缀稳定
```

然后在白名单里的测试群里真聊几句，打开「会话」页看完整提示词和它的思考。几个常见问题：

| 现象 | 先查 |
|---|---|
| 规则写了没效果 | 是不是和系统提示里某条固定规则打架；挪到角色卡第一节、写具体 |
| 话太多 / 太少 | 角色卡里有没有写死字数；参与度档位；响应档位滑条 |
| 某个工具从来不调 | 工具描述有没有写「什么时候用」；插件页这个扩展是不是真启用了 |
| 工具调了又自己复述一遍 | 工具描述里加「调用后不要再复述」 |
| 改了 Codex 大脑没反应 | 「Codex」页点那个聊天的「重置」 |
