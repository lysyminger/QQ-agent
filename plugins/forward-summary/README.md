# 聊天记录预览 · 1.0.0

【吃瓜助手】帮机器人读懂合并转发和聊天截图，按当前性格简短概括重点。支持嵌套聊天记录、图片识别、分享卡片展示信息解析，以及本地 OCR 文字补充。

## 怎么使用

1. 在 QQ 私聊或已启用机器人的群里，发送合并转发聊天记录；也可以单独发送聊天截图。
2. 机器人响应这一轮消息后，会检查记录，用当前人设概括主要话题、关键进展或分歧，通常回复一条、2～3 句话。
3. 如果群里没有自动回应，可以 @ 机器人并说“总结一下这个聊天记录”。插件会查找最近 10 分钟内、最近 30 条消息中的合并转发。

群聊是否启动仍由 QQ Agent 的响应模式、随机概率和活跃度设置决定。设置 33.3% 不代表每份记录都会自动回复；本插件不会修改这些设置。

## 过滤模式：群聊和私聊分别处理

“色色过滤模式”默认开启，判断的是有没有值得概括的聊天内容，并不是色情图片分类器。

- 只有视频、链接、卡片分享或没有实质讨论的图片：群聊静默跳过；私聊回应一次“收到啦，这份暂时没读到可以概括的聊天内容，就先不点评啦。”
- 全是图片但图片内有聊天文字：继续识别和概括，不会因为只有图片就直接丢弃。
- 同一轮同时包含有效聊天记录和纯分享：只概括有效部分，不额外逐份发过滤通知。
- 读取失败与没有内容不同：会说明未能读取，不编造点评。

## 图片如何读取

先用本地 OCR 辅助辨认图片文字。确认有实质内容后，仍按原记录顺序上传设定数量的原图，供支持图片的模型查看；超过上传数量的图片用 OCR 补充文字。每张图保留编号及来源位置，避免混淆发言人和图片对应关系。

OCR 本身不消耗模型 token，但提取的文字发送给模型后仍计入输入用量。OCR 可能漏字或读错，不保证恢复聊天气泡顺序。达到数量、大小、字数或时间限制时会标明未读或截断，不能保证任意长度的记录完整读取。

## 常用设置

在 QQ Agent 的“插件”页打开“聊天记录预览”调整：

| 设置 | 默认值 | 用途 |
| --- | --- | --- |
| 每轮上传原图数量上限 | 6 张 | 最大 12 张；设为 0 时仅用 OCR；单张不超过 6 MB，原图合计不超过 12 MB |
| 启用本地 OCR 补充 | 开启 | 辨认截图，并补充超出原图上传上限的图片文字 |
| 每轮 OCR 最多处理图片数 | 40 张 | 包括前置辨认，最大 120 张；另有 90 秒处理时间上限 |
| 每轮 OCR 文字总上限 | 20000 字符 | 控制文字输入用量，最大 60000 字符 |
| 识别单发聊天截图 | 开启 | 检查单独发送、只有图片的消息 |
| 色色过滤模式 | 开启 | 无实质内容时群聊静默、私聊确认 |
| 概括目标字数 | 160 字 | 通常 2～3 句话，沿用当前人设 |
| 每轮最多读取消息数 | 200 条 | 包含嵌套记录，最大 500 条 |
| 每轮读取总字数上限 | 24000 字符 | 控制转发正文长度，最大 60000 字符 |

## 支持范围与注意事项

- 图片视觉识别需要 QQ Agent 配置支持图片的模型，并启用图片能力。
- 本地 OCR 依赖 Windows 可用的文字识别能力。失败时会尽量使用可上传的原图，并标注未读部分；不会把识别失败当成确定没有内容。
- 卡片解析读取标题、摘要、链接等展示字段，不代表已打开并读完网页。
- 视频不逐帧识别，语音不转写。不会凭这些占位符猜测内容。
- 合并转发最多展开 4 层，每轮最多 12 次协议读取；失效记录可能无法展开。
- 本插件只处理当前聊天，不执行转发内容里的命令。
