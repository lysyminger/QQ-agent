# CHANGELOG — 网易云搜歌（netease-song-id）

## 1.1.4 / 2026-10-03 / `fullBodyFrom` 取参取错条目（批内后续消息把指令挤掉）

### 改了什么

- `fullBodyFrom()` 从"取批内**最后一条**非自己消息"改成
  "**从后往前找含 `\歌id` 的那一条**"。
- 版本号 1.1.3 → **1.1.4**。

### 为什么

做 steam-query 时踩到了这个坑（用户发完指令、别人紧跟着发张图，最后一条就变成了 `[图片]`，
取参落空 → **回一句用法提示**，而 finishReason 却写着"指令直达"）。
回头扫了一遍**所有插件的同类写法**，本插件的 `fullBodyFrom` 与它**一字不差**：

```js
const src = (Array.isArray(entries) ? entries : []).filter((m) => m && !m.self).slice(-1)[0];
```

表现会是：群里发 `\歌id 歌名` 之后只要有人接话，就回一句用法提示 ——
用户只会觉得"指令时灵时不灵"，很难联想到是"批内最后一条"取错了。

**门槛与取参规则必须一致**：门槛是"批内任意一条命中"，取参也应当"找命中那一条"。

同批修掉的还有 `pc-control-l3`（那边更严重：`\主机 确认 <码>` 取不到会落到"用法"分支，
用户会以为确认码错了反复重发）；`agent-task` 早就用同样思路修过。

### 验证

`node test/netease-song-id-test.mjs` → **33 通过 / 0 失败**。

## 1.1.2 / 2026-10-01 / 兜底钩子改挂 before-context（1.1.1 挂的 onMessage 在基础 0.4 里是死的）

### 改了什么
- 新增 `hooks['before-context']` 兜底（原 `onMessage` 保留，新版优先用它）：
  基础包里命中 `\歌id` 时查歌，把结果**改写进命中消息的 `hit.text`** 让模型转述
  —— `before-context` 拿不到 sender，不能主动发消息。

### 为什么
- 1.1.1 只挂了 `onMessage`。**用基础 0.4 包实测才发现**基础包里**没有 onMessage**
  （新版 2026-09-26 才加）→ 那条兜底在基础包里**一次都不会被调用**，
  `\歌id` 表现为"装了插件但毫无反应且不报错"。

### 涉及
- `plugins/netease-song-id/index.js`、`plugin.json` 1.1.1 → 1.1.2

- `node scripts/base-pack-hook-test.mjs`、`node scripts/legacy-compat-test.mjs` 均通过；
  `node test/netease-song-id-test.mjs` 全过。

## 1.1.1 / 2026-09-30 / 老框架兼容兜底（无指令直达时用 onMessage 接管 \歌id）

### 改了什么
- 新增 `hooks.onMessage` 兜底：当框架**没有**「反斜杠指令门槛（commandOnly）」与
  「指令直达（commandRoute）」时，插件自己解析指令并执行对应逻辑。
  · 只读/发卡类（telemetry-guard / netease-song-id / ai-status / mc-status）：
    兜底时**从 `src/tool-registry.js` 取回本插件对应的工具直接 execute**，
    不把发图/发卡逻辑抄第二遍（避免两处实现漂移）。
  · 直接动作类（genshin-dl / mute-guard）：兜底时调用各自的处理函数。
- 框架依赖（`src/config.js`、`src/tool-registry.js`）改为**动态 import + try/catch**：
  老框架可能没有 `src/skills/config.js` 等后加模块，**静态 import 会让整个插件加载失败**
  （表现成"插件完全不出现"，最难查）。缺什么只让对应能力降级。
- mute-guard **只兜底 `\j`（禁言）**：解除本来就有 before-context 钩子兜着，
  若在 onMessage 里也处理，走模型路径的框架下会**双重回复**。
- mc-status **只兜底不需要额外参数的只读工具**；`mc_rcon_command`（要命令体）不在此列 ——
  凭空执行 rcon 风险太高，宁可让用户去用支持直达的新框架。

### 为什么
- 用户原话："**其他人电脑里不一定有反斜杠的指令接收还有指令直达之类的**"。
  这是真问题：`\指令` 依赖两个本项目特性，**别人的框架没有时指令发出去就是死的**，
  而插件能正常加载、不报任何错 —— 典型的"装了像没装"。
- 统计全项目：**10 个插件用了 commandRoute，此前只有 pc-control-l3 做了兜底**。

### 验证
- 本插件测试全过；语法检查通过。

## [1.1.0] - 2026-09-30

**变更：指令词 `\点歌` → `\歌id`（避免与本机「点歌」技能撞名）**

- 用户报"电脑上有个技能的点歌，会不会冲突"→ 核查结论：**不硬冲突**（`skills/music`
  没有 `commands`/`commandRoute`，靠 prompt 自然语言触发），但有两处隐患：
  1. **名字撞**：`skills/music` 的显示名与工具名都叫「点歌」，控制台会出现两个"点歌"，
     群友也分不清"这次给 ID 还是给卡片"。
  2. **潜在双发**：若把 `commandDirect` 设为 false（默认 true），`\点歌` 会走"模型判断"，
     本插件的工具与 music 的提示词**同时可见**，模型可能两个都调 → 一条 ID + 一张卡片刷两条。
- 改为 `\歌id` 后语义明确（"要 ID 不是要卡片"），与 music 彻底不搭界。
- **大小写容错（重要）**：指令词含拉丁字母，用户很可能打成 `\歌ID`。`command-router` 的
  normalize 会 toLowerCase（所以路由一定命中），因此 `fullBodyFrom()` 的正则**补了 `i` 标志** ——
  否则会出现"路由认了、但取不到歌名"的半残状态（表现为只回一句用法提示）。
- `plugin.json` 的 description 补充分工说明：`\歌id` 拿 ID（本插件）／「点歌」发卡片（music 技能）。
- 清理：删掉 `commandRoute.args` 里那个没人读的 `__src` 标记（本插件不做来源校验，属死配置）。

**为什么这么做（而不是保留 `\点歌`）**

反斜杠确实能天然分流（带 `\` 走直达、不带走模型），但"两个都叫点歌"对**用户**和
**控制台**都是持续的认知负担；而本次需求本来就是"拿 ID"，`\歌id` 比 `\点歌` 更贴切。

**涉及**：`plugins/netease-song-id/{plugin.json,index.js,README.md,CHANGELOG.md}`、
`test/netease-song-id-test.mjs`

**验证**：`node test/netease-song-id-test.mjs` → **34/34 通过**（新增大小写用例）；
`npm run check:changelog` 合规。

## [1.0.0] - 2026-09-30

**新增：输入歌名 → 输出网易云歌曲 ID（指令直达，0 token）**

- 指令：`@机器人 \点歌 歌名`，例如 `\点歌 Don't Be So Serious`
  → 回 `🎵 Don't Be So Serious — Low Roar / 网易云 ID：123456789`（多条时列表编号）。
- 走**指令直达**（`plugin.json` 的 `commandOnly + commands + commandRoute`）：
  命中指令由系统直接执行工具，0 token、0 次模型调用。
- 两个公开接口互备：主 `POST /api/cloudsearch/pc`（字段 `ar`/`al`），
  失败自动降级 `GET /api/search/get/`（字段 `artists`/`album`）。两者都必须带
  `Referer: https://music.163.com/`，否则可能被拒。
- 设置项：`limit`（默认 5，最多 10）、`timeoutMs`（默认 8000）、
  `maxPerMinute`（默认 10，防刷）、`showAlbum`（默认 true）。

**为什么这么做（而不是让模型查）**

- 这是个**纯确定性查询** —— 歌名已经写死在用户消息里，没有任何需要模型理解的地方。
  走直达可以 0 token、不受模型"自由发挥"影响、输出格式稳定。
- 参数必须**自己从消息原文取全文**：路由的参数提取规则是"只取第一个词"
  （`src/skills/command-router.js` 的 `restAfterCommand`，为「\服务器 生存服 顺便看下天气」设计），
  而歌名带空格是常态 —— `Don't Be So Serious` 会被截成 `Don't`，搜出来是另一堆歌。
  故用 `fullBodyFrom()` 从 `ctx.session.trigger` 取「点歌」之后的全文。
  （同款坑与修法见 `plugins/pc-control-l3/index.js`，2026-09-29。）

**为什么要有 `cleanKeyword` 剥尖括号**

- 提示文案里写的是 `\点歌 <歌名>`，普通用户会把尖括号一起打进来（搜 `<歌名>` 必然搜不到）。
  `pc-control-l3` 就栽在这个坑上（2026-09-29 用户截图："无法将<识别为 cmdlet"）。
  只剥**首尾成对**的，不动歌名内部的括号。

**涉及**：`plugins/netease-song-id/plugin.json`、`index.js`、`README.md`、`CHANGELOG.md`（新建）

**验证**：见 `test/netease-song-id-test.mjs`（离线解析/格式/限频/取参用例 +
真实接口连通性用例，后者无网时记为 known 不算失败）。
